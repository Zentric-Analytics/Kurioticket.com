# Stage 1 native search error handling

The shared native transport preserves timeout, UI deadline, caller cancellation and supersession during body consumption instead of converting them to malformed-response errors. Syntax errors map to invalid-json; invalid top-level/search result-array contracts map to invalid-schema; network errors and non-validation HTTP denials remain distinct. No exception URL, raw provider message or body is used for the new error descriptions. Existing status-specific validation, rate-limit, unavailable and server classifications remain intact.

Flight result state maps internal categories to fixed localized timeout, connection or unreadable-response copy across supported locales, with the existing localized generic fallback. Cancellation and sequence/search-key guards continue to prevent stale overwrites. Canonical acceptance tolerates malformed rows without throwing away valid rows from another supplier. Partial inventory and genuine empty results retain their existing presentation semantics. Deadlines remain 35,000 ms API and 37,000 ms UI; this unit does not establish recovery or change the flight supplier identity.

Focused tests execute actual shared transport with controlled header/body interruption and the configured timer, all cancellation causes, JSON/schema/HTTP/network cases, partial/empty responses, safe localized copy and canonical row acceptance. Full native/account/handoff tests protect shared iOS/Android behavior. Rollback is a scoped revert of this unit; no environment or database change is required. Stage 1 owner approval is required before integration/delivery; genuine flight identity renewal remains separately gated.

Native transport and the flight controller record abort causes in a WeakMap before aborting. This avoids relying on AbortSignal.reason, which the installed React Native abort-controller does not retain. Tests run actual headers/body timer expiry and explicit caller/superseded/UI cancellation against that installed polyfill.
