Use additive metadata and existing persistence where sufficient. No new infrastructure, external SDK, dependency or Stage 06 UI.

## Stage 05

Saved state now separates confirmed records from pending operations. Concurrent failures roll back only their own optimistic changes; cache writes are ordered; stale refreshes cannot replace mutations; migration clears legacy records only after successful synchronization; old repositories deactivate and clear private caches after account changes/sign-out. Saved API calls are explicitly account-bound, and account-owned native responses are discarded after a session transition. Already-removed records reconcile safely. Exact server save retries share transactionally locked existing storage (Cars use the existing unique upsert); no historical records are deleted or merged.

Account preferences serialize writes, skip resume hydration during pending writes, restore confirmed state on failed synchronization, and never cache an unsuccessful optimistic value as authoritative. First-time initialization is atomic/create-only via additive initializeIfAbsent; an intervening save by another device wins. Guest preferences remain separate in the native coordinator. Website Saved/Recent now refreshes on resume, guards owner/request generations and pending deletes, and hides another account's records. Website preference hydration retries on resume and can refresh an already-account-sourced locale while preserving explicit manual display overrides.

Native saved/recent/price-alert/trip and travel/email-preference flows refresh on focus/resume and reset private screen state on account changes. Saved/recent/alerts/trips have user-triggered refresh controls. Existing account services remain authoritative; no real-time service or alternate account store. Notifications retain their existing pagination/refresh API and support retains existing ticket/email flow; full native support conversation sync and a notification-wide retained-screen account-reset audit remain deferred messaging work. Partner-confirmed trips remain distinct from saved planning records.

Verification: complete native suite 2,326 passed; mobile and root TypeScript passed; 37 focused shared saved-adapter/preferences/monitoring/browser-resume tests passed; touched root runtime/service files passed ESLint. Contract fixtures exercised all four saved types through actual web/native handlers, account isolation, retries and deletion.
