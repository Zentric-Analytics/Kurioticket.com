# Structured KAYAK Flight fare information

Implemented on `fix/mobile-flight-details-surface-consistency`, starting from dev `3b69ab94aff5fb9a613ae27e94f79a2a7e7ffecf`. The existing branch was fast-forwarded safely before implementation. `work` was not touched.

## Result and scope

Flight Details no longer renders SupplierInformation on desktop/mobile web or NativeSupplierInformation on native. There is no replacement raw-facts section or fifth tab. Compare deals markup/styling, hero styling, itinerary card design, and unrelated verticals are unchanged. Aircraft/duration enrichment fills existing itinerary fields rather than redesigning them.

One structured-source normalizer, `src/services/travel/kayakFlightInformation.ts`, is shared through the normalized Flight contract. All three tab implementations consume its output. React components never classify KAYAK labels.

## Exact mappings

| KAYAK source | Destination |
| --- | --- |
| `option.fareFamily` string/name/displayName | Fare details: fare brand/family |
| `option.segmentFares[].cabin.displayName` | Matching segment cabin in Fare details; no raw code fallback |
| `segment.equipmentTypeName` | `FlightSegment.aircraft.name`, existing aircraft presentation and Fare details |
| Numeric `segment.duration` in provider minutes | `FlightSegment.duration` in ISO duration form; no extra duplicate tab row |
| Supported `qualityItems` seat/power/powerNegative/entertainment/food/wifi/redEye codes with safe descriptions | Typed onboard seat, power/USB, entertainment, meal, Wi-Fi and overnight facts in Fare details |
| Explicit fee-qualified quality items | Optional extras, with exact price when supplied or Available for a fee |
| `option.fees.carryOnBag` / `checkedBag` | Fare conditions: included/not included/not allowed/unknown or supplied charge, without raw enums |
| `option.conditions.change` / `refund`, explicit penalties | Existing structured conditions in Fare conditions |
| `airline.baggagePolicies`, explicit carry-on/checked descriptions/restrictions | Carrier-labelled Airline baggage policy group in Fare conditions, never purchased inclusion |
| `option.optionalServices` explicitly marked optional | Optional extras with description/type, price/currency when supplied, quantity, traveler count, journey context, per-traveler flag |
| Exact numeric base/total and explicitly supplied tax amount, with matching verified displayed total/currency/source price mode | Existing Price breakdown; scale only the established perPerson mode, never infer taxes |

Descriptions preserve partial availability (Power (some rows) & USB), seat layout/pitch, and provider meal/entertainment wording. Wi-Fi without explicit price remains a feature description, not an invented free/included claim. Fee-based services preserve supplied traveler/quantity metadata, including when the amount is unknown.

## Hidden and internal data

Raw segment IDs, cabin/quality codes, bag ordinals as schema rows, segment type, raw object paths, badges, duplicate formatted/numeric prices, unknown fields, and transport identifiers are not displayed. Only supported quality semantics and explicit policy shapes are mapped.

Sanitized raw `suppliedFacts` and unmapped diagnostics can remain in `NormalizedFlightResult.rawProviderReference`, which is server/cache-only. `FlightProviderDetails` no longer has `suppliedFacts`. `toPublicFlight` explicitly projects supported provider fields; Details uses that same safe projection. Unknown provider fields and raw diagnostics are absent from public Flight search and Details serialization. Projection does not mutate cached input.

Legacy KAYAK snapshots with the former `providerDetails.suppliedFacts` marker omit all unverified fare terms, including those generated by the old flattened-fee fallback. Fare-choice distinguishing terms use the safe projection too. Fresh normalized KAYAK facts and Duffel fare terms are retained.

Unknown/future fields, unsupported quality codes, unverified price breakdowns, ambiguous duplicate segment matches, and transport-reference-only service scope formats are deliberately not guessed. Safe useful unknown facts remain internal where captured; credential-bearing text and transport links are rejected. Supporting new shapes requires an explicit mapping and regression test.

The native shared supplier component remains for its legitimate Hotel usages. The standalone web helper and its escaping test are retained, but Flight Details has no import or usage of it.

## Rulings and limitations

1. Cloud skill helper executables were unavailable; equivalent plan-specific progress/test/commit evidence was maintained manually.
2. Initially preserve unrelated baseline failures and existing Compare deals/Hotel UI; their assertions were fixed upstream and pass after the dev update.
3. Retain shared supplier helpers while removing every Flight usage; native Hotel still needs its helper.
4. Move the temporary baseline archive outside the project so root TypeScript cannot ingest its archived native shim; production configuration stays unchanged.
5. Unknown undocumented shapes and transport-ID-only scope are unmapped, not inferred. Cost: those facts need a deliberate future mapping before customers can see them.
6. Native policy-only empty-state correction was addressed despite being graded minor, because claiming supplied conditions are unavailable contradicts this task's truthfulness requirement.
